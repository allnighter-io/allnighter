Sidebar redesign

The conversation list, rebuilt around how Allnighter actually works: one project at a time. Threads group under their project; every row collapses to a single line. This spec covers the rules, anatomy, states, behaviors, and exact tokens for the Swift build.

Proposal v2Interactive mockup → companion fileTokens: Allnighter DS

Why it changed

Allnighter is scoped per project — so the sidebar leads with the project and lets each row carry almost nothing. The old row stacked six signals (worker avatar, lane badge, a verbose status pill, a worker stack, title, time) across two lines. We scan for two things: which thread, and has it changed since I looked. Everything else is detail-view information.

The dot means exactly one thing: unread.

We dropped colored status dots entirely. Red/green “failed vs done” was theater — the underlying state isn’t reliable enough to color a dot we’d trust at a glance. A single amber dot for unread is honest and 10× clearer. Open a thread and the dot clears.

Anatomy

Row

[ unread dot ] · title · · · time

Single line, ~32 pt tall. Title truncates with ellipsis. On hover (macOS) the time is replaced by pin + archive actions.

Structure

Pinned — flat section at top, cross-project, for threads you pinned.
Projects — section header with filter + new-project actions; then one collapsible group per project. Groups show 4 rows then “N more”.

Behaviors

  • Open a thread → its unread dot clears; the project’s aggregate dot clears when none of its threads are unread.
  • Pin → floats the thread into the flat Pinned section at the top (removed from its project group while pinned). Toggle to unpin.
  • Archive → removes the thread from the list.
  • New work order → primary amber button (starts a chat); also a + on each project header for a project-scoped chat.
  • New project → folder-plus in the Projects section header. Filter sits beside it.
  • Collapse a project (tap header) and See more (“N more”) past 4 rows.

SwiftUI implementation notes

This maps cleanly to a native List with sections — pin/archive become swipe actions, and on iOS the hover affordances move to swipe + context menu.

// Pinned + one Section per project
List(selection: $openThreadID) {
  if !pinned.isEmpty {
    Section("Pinned") { ForEach(pinned) { ThreadRow(thread: $0) } }
  }
  ForEach(projects) { project in
    Section {
      ForEach(project.visibleThreads) { ThreadRow(thread: $0) }
    } header: { ProjectHeader(project) }   // folder · name · unread dot · ＋
  }
}
.listStyle(.sidebar)

struct ThreadRow: View {
  let thread: Thread
  var body: some View {
    HStack(spacing: 9) {
      Circle().frame(width: 7, height: 7)
        .foregroundStyle(thread.isUnread ? Color.accentAmber : .clear)
      Text(thread.title).lineLimit(1)
        .font(.system(size: 13, weight: thread.isUnread ? .semibold : .regular))
        .foregroundStyle(thread.isUnread ? .textPrimary : .textMuted)
      Spacer()
      Text(thread.relativeTime)
        .font(.system(size: 10, design: .monospaced))
        .foregroundStyle(.textFaint)
    }
    .swipeActions(edge: .leading)  { Button("Pin")     { pin(thread) }.tint(.accentAmber) }
    .swipeActions(edge: .trailing) { Button("Archive") { archive(thread) } }
  }
}
  • Unread is one boolean on the model — it drives dot, weight, and color together. Clear it in onAppear/on-select of the detail view.
  • Selection uses the amber leading rail (an inset RoundedRectangle overlay), not a full-row tint alone, so it reads on the sidebar material.
  • Project aggregate dot = project.threads.contains(where: \.isUnread).
  • Honor Dynamic Type — the px sizes above are the design baseline; prefer scalable .system(size:) and let titles grow.
  • Amber is the only chromatic accent — keep status/lane out of the row entirely.
