# GUI Surface Architecture

**Status:** Canonical
**Scope:** The app's UI surfaces and how they map to the design-system UI kits
and the MVP phases. Read before adding or materially changing a surface (Tier C).

Every surface listed has a visual reference in `docs/design-system/ui_kits/` and
a build owner in `docs/mvp/`. The kit is the *visual* target; the phase doc is
the *behavioral* contract. Where they disagree, the phase doc wins for behavior
and the design system wins for visuals — reconcile, do not fork.

## macOS — Team run window (`ui_kits/team/`, legacy visual kit name)

The MVP surface. Built in `docs/mvp/03_Mac_App_And_Run_Loop.md` (shell + run
loop) and `04_Synthesis_And_Plan.md` (synthesis).

| Surface | What it shows | Build owner |
| --- | --- | --- |
| Menu-bar item (`MenuBarExtra`) | Status / quick entry | mvp/03 |
| Prompt composer | Multiline prompt + "Ask team" / "Run team" | mvp/03 |
| Team view | Configured workers as `Skill | Model` rows + health badges | mvp/03 |
| Live run grid | One chip/row per worker: `queued`/`running`/`done`/`failed`/`timed_out`, elapsed, global Stop | mvp/03 |
| Response viewer | Per-worker answers (cards/tabs, Markdown, copy); `manual_paste` shows a paste box | mvp/03 |
| Plan bar + plan | The Opus-written plan / winner | mvp/04 |
| Model/team settings | Enable/disable models, set plan writer, edit model label/manifest | mvp/03 (full Doctor UI in mvp/05) |
| Run history + presets | Past runs, saved presets | mvp/05 |

## macOS — Review / Review Board (`ui_kits/review/`)

The review chain surfaces — workflow presets, stage primitives, return review.
Behavioral contract: `docs/mvp/RB0_Review_Workflow_Overview.md` and the routed
`RB1`–`RB6` docs.

## iOS — Floor Manager (`ui_kits/ios-floor-manager/`, `ui_kits/review-ios/`)

Parked roadmap; control-from-anywhere over Tailscale. Behavioral contract:
`docs/phases/ios/README.md`. Surfaces: Morning Pull, Active Lanes, the Draft
Race + picker-as-prompt wedge, and the iPhone review companion. These share
the same `@Observable` model as the Mac via the connection spine
(`docs/phases/ios/01_Connection_Spine.md`) — they render, they do not own truth.

## Adding a surface

1. Pick the tier in `GUI_Workflow.md`. New surface = Tier C minimum.
2. Confirm the visual kit in `docs/design-system/ui_kits/` (or add a specimen
   first if none exists — that work belongs to the design system, not here).
3. Write a brief in `docs/gui/surfaces/<surface>/brief.md`
   (template: `surfaces/README.md`) naming states, the owning core contract, and
   the field-ownership ledger.
4. Build views that read the run store; add presenter/state tests per
   `GUI_Workflow.md` §6.
