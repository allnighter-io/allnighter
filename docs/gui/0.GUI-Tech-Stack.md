# GUI Tech Stack

**Status:** Reference
**Scope:** The UI layer only. The full stack lives in
`docs/operations/TechStack.md`; the locked MVP architecture in
`docs/mvp/00_MVP_Architecture.md`. This doc names what a GUI agent needs.

## Stack

- **Language:** Swift 6 language mode (strict concurrency).
- **UI:** SwiftUI + Observation (`@Observable`) — macOS `MenuBarExtra` (status
  item) + a main window; AppKit only where SwiftUI can't reach. iOS companion is
  SwiftUI over Tailscale.
- **Shared contracts:** `AllnighterCore` (+ `AllnighterEngine` on Mac) — models,
  stores, services, JSON envelopes, fixtures. **Views read from here; views are
  not shared across app targets.**
- **Mac app target:** `Apps/AllnighterMac/` (XcodeGen) — local truth, full bench.
- **iOS app target:** `Apps/AllnighteriOS/` — remote PM shell over the control
  plane; separate SwiftUI codebase from Mac.
- **Floor:** macOS 14 Sonoma+ (mature `MenuBarExtra`, `Observation`).

## Platform shells (Mac vs iOS)

Views are **not** shared between Mac and iOS. Both apps present the same
**CLI/MCP contract** through independent SwiftUI shells. Full policy:
`GUI_Workflow.md` §5.

- Do not add `Packages/AllnighterUI` or cross-import `View` types between
  `AllnighterMac` and `AllnighteriOS` without founder escalation.
- Design tokens align via `docs/design-system/`; each app keeps its own Swift
  color/spacing constants (`ALColor` vs `IOSColor`).

## State Flow (the one rule that shapes every view)

```text
engine/coordinator ──RunEvent AsyncStream──▶ @Observable run store ──▶ SwiftUI views
```

- An `@Observable` run store subscribes to the coordinator's `RunEvent`
  `AsyncStream` and applies events idempotently (upsert).
- Owned SwiftUI state follows `docs/operations/SwiftUI_State_Rules.md`: no
  `ObservableObject`, `@Published`, `@ObservedObject`, `@StateObject`, or
  `@EnvironmentObject` in app-facing code.
- **The UI never mutates truth directly** (`docs/mvp/00` §6). Views render the
  store and send intents; they do not invent run state, worker status, or
  answers. iOS and Mac can share the same **Core contract** while keeping
  separate view codebases (`GUI_Workflow.md` §5).

## Where Design Tokens Enter The App

The design system (`docs/design-system/`) is the **visual SSOT**. Its
`tokens/*.css` and component JSX are the prototype/specimen form. The production
app consumes the *same* values as Swift constants/asset-catalog colors — see
`docs/design-system/production.md` for the token-source-of-truth rule. Do not
hard-code hex in views; map to the named tokens.
