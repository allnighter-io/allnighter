## ⛔ What is DEAD — and why it stays dead (share this with mentors)

Two earlier ideas were cut after the founder's review. They were **100x more
complex than this problem needs.** Do **not** reintroduce them.

### OCR is DEAD — rejected, not deferred

- **Where it came from:** an earlier draft wanted to pull the text off an attached
  screenshot to "seed the content" for redesigns.
- **Why it's wrong:** Apple Vision OCR is genuinely bad on UI screenshots (small
  labels, icon-glyphs-as-text, stylized fonts, status-bar chrome) — the founder has
  used it extensively and it fails. Worse, it solved a problem we don't have:
- **The kill shot:** the models **see**. The image engines look at your screenshot
  natively and improve it. **LLM image recognition replaces OCR entirely** — better,
  free, and already how you actually work. There is nothing OCR provided that the
  multimodal models don't do better. *We never read pixels for text; we hand the
  model the image.*

### HTML rendering is DEAD — rejected, not deferred

The earlier draft made the **coding CLIs** (Claude Code, Grok, Codex) emit
self-contained HTML, then built a pipeline to render that HTML into pictures so the
board could show them. That single premise dragged in an enormous tail:

- a headless **WKWebView render harness** + a Chromium fallback,
- a strict **"self-contained HTML" dispatch contract** fought across heterogeneous CLIs,
- a synthesized **content fixture** (to make rendered HTML comparable),
- **pHash / DOM divergence** measurement + automatic **rerolls**,
- **hermetic-network** blocking, bundled Tailwind, and a pixel-**fidelity gate**.

**Why it's all dead:** your subscriptions already include **image engines** —
**Grok Imagine, Gemini (Nano Banana Pro), ChatGPT's image engine** — that emit
finished design images **directly, for free**, and are **better designers** than a
coding agent writing Tailwind. So:

> **Don't make coding agents cosplay as designers and then build a rendering
> pipeline to look at their homework. Let image engines design. Let coding agents
> build.** Each does the thing it is actually good at.

Killing HTML deletes the **entire** list above. The **image is the unit** — already
a picture, already comparable, no render step, no fixture, no pHash, no gates.

**The honest tradeoff (state it, don't hide it):** the design council's immediate
output is an **image** — concept art, not shippable code. That's fine, because **code
still happens** — at the **Build step**, when you pick an image and an agent
implements it (Design2). Image engines design; coding agents build; nobody is forced
to be what they're bad at. This is exactly your real workflow today (you get images
from ChatGPT/Gemini and they're amazing) — plus **range** (a council, not one shot)
and a **zero-paste path to real code**.

## The Loop (the whole product)

```text
pick the Design chip  ·  attach a screenshot ("improve this")  ·  optional prompt
-> Allnighter fans the screenshot + each design persona out to the IMAGE ENGINES
   you already pay for (Grok Imagine, Gemini Nano Banana Pro, ChatGPT image, ...)
-> each returns a finished design image; the BOARD shows them side by side, same scale
-> you look first, you pick the one you love (your eyes decide)
-> "Build this" -> you choose which CLI implements it (just like the build council)
-> that coding agent reads the chosen image + builds the real code in your repo
No OCR. No HTML render pipeline. No copy/paste.
```

Fan out → board → pick → build. The design module owns only the first three; the
fourth is Lane 1's executor dispatch (RB4), reused.

## Architecture: two engines, each to its strength

| Job | Who does it | Why |
| --- | --- | --- |
| **Design** (produce options) | the **image engines** (Grok Imagine / Gemini / ChatGPT image), one per design persona | purpose-built to make things look great from a screenshot; free under your subscriptions |
| **Decide** (pick the winner) | **you** | taste is yours; the board is the first thing you see, before any AI voice |
| **Build** (turn it into code) | a **coding CLI you choose** (Claude Code / Codex / Grok / …) | coding agents are great builders; they read the chosen image and implement it |

The design seats need **image generation**; the build step needs an agent that can
**read an image**. Both are capabilities we **verify on-device** (Doctor flags), not
assume.

## Product Laws

- **Image engines design; coding agents build.** Never force one to be the other.
- **The board is the first truth surface.** You see the options before any AI
  verdict. Your eyes decide.
- **You pick; AI advises.** Any "lead designer" critique is advisory and speaks
  *after* you've looked (Design2). It never casts the vote.
- **The image is the unit.** No render step, no HTML contract, no content fixture.
  Workers emit images; the board shows them.
- **Zero marginal cost.** Only the image engines you already pay for via
  subscription. No API keys, no paid image gen, nothing uploaded to a third party
  beyond the CLIs you already use.
- **Code comes from the build step.** The design council's output is images; "Build
  this" turns the chosen image into code via a CLI you select (RB4).
- **Capabilities are verified, never assumed.** `canGenerateImages` (design seats)
  and `canReadImages` (build/critique) are Doctor-checked; missing → honest skip or
  fallback, never a silent failure.
- **No silent mode switch.** Design mode is the Design chip (or a result-side
  confirm), never auto-flipped.
- **Cost is never silent.** The `CallPlan` shows how many image generations a run
  will request before you commit.

## Vocabulary

| Term | Meaning |
| --- | --- |
| **Design run** | A council run whose unit is a generated image and whose verdict is human taste. A `WorkflowPreset` flavor, not a separate app. |
| **Image engine** | A subscription model that generates images (Grok Imagine, Gemini Nano Banana Pro, ChatGPT image). Reached through its CLI, headless. |
| **Design persona** | A short, editable style direction appended to the design prompt (minimal / bold / editorial / on-brand). The source of range. |
| **The board** | The gallery of generated design options at identical scale — the hero view. |
| **Build this** | The handoff: the chosen image → a user-selected coding CLI implements it (reuses RB4 direct dispatch). |
| **Lead designer** (optional) | An advisory critique that names tradeoffs *after* you've looked. Never the verdict. (Design2.) |

## Personas (light — range is the product)

Range comes from **different image engines × a few persona prompts**. Personas are
**one-line editable style directions**, not structural essays:

| Persona | Direction (appended to the prompt) |
| --- | --- |
| `minimal` | restraint, whitespace, type-led; strip the noise |
| `bold` | high contrast, big type, opinionated color |
| `editorial` | break the generic SaaS look; magazine/dense — while staying recognizably the same screen |
| `on_brand` | match the product's look (palette/type from the screenshot or a brand reference) |

Default = 3–4 options spread across engines × personas. The user can edit, add, or
fork a persona. If options come back too similar, the user clicks **"more / re-roll"**
— no automated divergence subsystem (that died with HTML).

## Detection

- **Prompt-side (v1):** a Design chip in the composer; attach a screenshot. The user
  tells us — no fragile classifier.
- **Result-side (later):** if a run's results are images, offer "view as a board?"
- **Mixed prompts** are out of scope; the user picks the chip.

## Artifact Contract

`run.json` is truth; files are derived.

```text
run_<id>/
  design_request.json     # prompt + persona set + attached screenshot ref + target shape (mobile/desktop)
  screenshot.png          # the attached "before" (if any); shown, never OCR'd
  option_<seatId>.png     # the generated design image per seat (the unit)
  board.json              # ordered gallery: seatId, engine, persona, imagePath
  chosen_option.json      # the human pick + rationale (logged for taste memory)
  build_brief.md          # the handoff to the implementer CLI (Design2)

```

## Design Activation Gate (run before trusting the machinery)

The earlier gate evaluated render comparability — dead. The new gate is simpler and
about the only things that matter now. Run **three real prompts** (a screenshot
redesign, a greenfield screen, and a "make this not look like AI slop"):

1. **Capability** — at least one subscription CLI generates an image **headlessly,
   at $0** (founder has seen Grok Imagine + Gemini do it; verify and record which).
2. **A board you'd pick from** — 3–4 options come back, side by side, clearly
   different enough that a non-designer picks a favorite in < 60s.
3. **Build works** — "Build this" hands the chosen image to a coding CLI that
   **reads the image** and produces plausible real code.

If no CLI generates images headlessly, **stop** — the whole premise needs a
different invocation path. Record the result and the per-worker capability flags.

## Moat

claude.ai/design and ChatGPT give you **one** pretty image and **no path to code**.
You get: a **council** (range across engines × personas), **your taste** as the
verdict, and a **zero-paste jump from the chosen image to real code** via the CLI you
choose — in the **same tool as your build council**. Image engines design, coding
agents build, you decide, and you never leave Allnighter.
