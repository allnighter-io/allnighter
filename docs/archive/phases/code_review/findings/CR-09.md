# CR-09 — TimelineVisibility scroll and read-clear

## Summary
`TimelineVisibility.swift` wires viewport-intersection preferences to a read-clear
cursor and owns the timeline auto-scroll policy. The read-clear path has one
O(n²) turn lookup that runs on every scroll frame, an intersection threshold
that silently drops turns taller than ~4× the viewport, and no throttling on
`report()`. The auto-scroll helpers are mostly sound but `scrollToBottom`'s
deferred second pass is non-animated and unconditional, and `liveContentSignal`
uses wrapping `&+` for a monotonic signal. None are P0; three are real P1 wins.

## Findings

### P1 — Quadratic turn lookup in `visibleTurnIdsForReadClear`
- **Invariant:** Read-clear must stay linear in turn count; it runs every scroll frame.
- **Evidence:** TimelineVisibility.swift:33 — `thread.turns.first(where: { $0.id == id })`
  inside `thread.turns.map(\.id).filter { ... }`. The outer map is O(n) and the inner
  `first(where:)` is O(n), so the whole filter is O(n²). The turn being looked up is
  the same turn the map just yielded, so the lookup is also redundant.
- **Impact estimate:** n=500 turns → ~125k id comparisons per `report()` call.
  `report()` fires ~2× per scroll frame (turnFrames + viewport change, see P1 below),
  so ~250k comparisons/frame; at 60 fps that is ~15M String comparisons/sec on the
  main thread. Long threads (1k+ turns) will drop frames during scroll.
- **Suggested fix:** Iterate `thread.turns` directly and drop the inner lookup:
  ```swift
  return thread.turns.filter { turn in
      guard geometricallyVisible.contains(turn.id) else { return false }
      return UnreadDerivation.isUnreadEligible(turn)
          ? countsTowardReadClear(turn)
          : true
  }.map(\.id)
  ```
  This makes the pass O(n) and removes the redundant lookup entirely.
- **Suggested slice:** read-clear-linear-pass

### P1 — Tall-turn intersection threshold never clears long answers
- **Invariant:** A turn that fills the viewport must count as visible regardless of its own height.
- **Evidence:** TimelineVisibility.swift:50-51 —
  `let ratio = viewport.intersection(frame).height / frame.height; return ratio >= threshold`.
  The ratio is normalized to `frame.height`, so a turn taller than the viewport is
  penalized: when `frame.height > viewport.height / threshold` (i.e. > 4× viewport at
  threshold 0.25), even a fully-on-screen turn has `ratio = viewport.height / frame.height
  < 0.25` and is dropped. Long streaming answers easily exceed 4× viewport height.
- **Impact estimate:** Any unread turn taller than ~4× the viewport that the user is
  actively reading will never be reported visible, so its unread state never clears.
  Affects long worker answers and long `manualPaste` system events. Medium blast radius
  but silent (no crash, just a stuck unread dot).
- **Suggested fix:** Normalize against the smaller of the two heights, or take the max
  of the two ratios, so a turn that fills the viewport always qualifies:
  ```swift
  let inter = viewport.intersection(frame).height
  let denom = min(frame.height, viewport.height)
  return denom > 0 && inter / denom >= threshold ? id : nil
  ```
- **Suggested slice:** tall-turn-read-clear-threshold

### P1 — `report()` unthrottled, fires 2× per scroll frame
- **Invariant:** Read-clear reporting should run at most once per settled frame, not once per preference key.
- **Evidence:** TimelineVisibility.swift:113-116 — three `onChange` hooks
  (`turnFrames`, `viewport`, `thread.turns.count`) all call `report()`. During a scroll
  gesture both `turnFrames` (every row's global frame shifts) and `viewport` change in
  the same run-loop pass, so `report()` fires twice per frame. Each call does the O(n²)
  work from the P1 above and forwards a fresh `[String]` to the view model.
- **Impact estimate:** Doubles the O(n²) cost from the first P1 (so ~250k→500k
  comparisons/frame at n=500). Even after the linear-pass fix, the redundant view-model
  forwarding and array rebuild are wasteful at 60 fps.
- **Suggested fix:** Coalesce into a single deferred pass — e.g. invalidate a
  `DispatchQueue.main.async` token and run `report()` once, or gate on a single
  `onChange(of: viewport)` plus a dirty flag set by the other two.
- **Suggested slice:** read-clear-coalesce

### P1 — Team-run read-clear gap for non-`workerChat` turn kinds
- **Invariant:** Every unread-eligible turn kind the user can read must be admissible to the read cursor.
- **Evidence:** TimelineVisibility.swift:7-19 — `countsTowardReadClear` admits only
  `.workerChat` and `.signInRequired` / `.manualPaste` system events; everything else
  returns `false`. In `visibleTurnIdsForReadClear` (line 37-39), an unread-eligible
  turn that returns `false` here is filtered out of the visible set, so it is never
  reported and its unread state never advances.
- **Impact estimate:** If team-run (Delegate / Execute) produces turns of a kind other
  than `.workerChat` that are `UnreadDerivation.isUnreadEligible`, those turns become
  permanently unread. Cannot confirm the turn-kind enum from the inlined source alone,
  so this is a gap to verify against `ThreadTurn.Kind`, not a confirmed bug.
- **Suggested fix:** Confirm the full set of turn kinds team-run emits; either admit the
  user-facing ones in `countsTowardReadClear`, or document that team-run results are
  always `.workerChat`. Do not silently default to `false` for new kinds — make the
  switch exhaustive and fail loud.
- **Suggested slice:** read-clear-team-run-kinds

### P2 — `scrollToBottom` deferred pass is non-animated and unconditional
- **Invariant:** A follow-up scroll pass should respect the `animated` flag and not fight the user.
- **Evidence:** TimelineVisibility.swift:219 — `DispatchQueue.main.async { scroll() }`
  runs `proxy.scrollTo(...)` outside any `withAnimation`, even when `animated: true`.
  It also fires unconditionally whether or not the first pass sufficed.
- **Impact estimate:** After an animated scroll-to-bottom, a non-animated jump can land
  one run-loop tick later, producing a visible hitch. If the user scrolls up inside
  that tick, the deferred pass yanks them back to the bottom. Narrow window (~16 ms)
  but observable on fast scroll.
- **Suggested fix:** Wrap the deferred pass in the same `animated` branch, and skip it
  if the user has since scrolled (check `isAtBottom` or a suppress flag before the
  deferred pass).

### P2 — `liveContentSignal` uses wrapping `&+` for a monotonic signal
- **Invariant:** A monotonic follow-scroll signal should not wrap.
- **Evidence:** TimelineVisibility.swift:240 —
  `(last.text?.count ?? 0) &+ (last.reasoningText?.count ?? 0)`. `&+` silently wraps on
  overflow. Realistic text lengths never overflow `Int`, so this is not a live bug, but
  the operator choice is semantically wrong for a "grows as the turn streams" signal and
  misreads as intentional overflow handling.
- **Suggested fix:** Use `+`. If a warning was being silenced, address the root cause
  rather than switching to `&+`.

### P2 — `report()` double-fires on new-turn append
- **Invariant:** One logical event should produce one `report()` call.
- **Evidence:** TimelineVisibility.swift:113-116 — appending a turn changes both
  `thread.turns.count` and `turnFrames` (new row reports a frame), so `report()` fires
  twice for one append. Subsumed by the P1 coalesce fix; listed separately because it is
  a distinct trigger path (count change) from the scroll case.
- **Suggested fix:** Same coalescing as the P1 above.

## False alarms ruled out
- **`TurnFramePreference.reduce` merge cost (line 61):** each `nextValue()` is a
  1-element dictionary from one row, so `merge` is O(1) per step and O(n) for the full
  reduction. Not a hot path; no change needed.
- **`viewport != .null` guard in `report()` (line 119):** correctly suppresses the
  initial pass before the scroll-view geometry reports a real frame. `null.intersects`
  would otherwise return false for all rows, so the guard is defensive but correct.
- **`frame.height > 0` guard in `geometricallyVisibleTurnIds` (line 49):** prevents the
  divide-by-zero on line 50. Correct.
- **`isAtBottom` slack logic (line 232):** `contentBottomY <= viewportBottomY + slack`
  correctly treats "near the bottom" as at-bottom for the RLS-S04 auto-follow gate.
  No issue.
- **Stale `frames` entries for removed turns:** `visibleTurnIdsForReadClear` iterates
  `thread.turns` (line 30), so frame entries for turns no longer in the thread are
  ignored. No leak into the visible set.
- **`scrollOnTurnCountChange` / `scrollOnThreadOpen` contention with user scroll:**
  both are gated by `suppressAutoScroll` (line 144, 154), which the caller sets when the
  user scrolls up. Contention is the caller's responsibility, not a defect in this file.
- **`liveContentSignal` returning 0 when not running (line 239):** correct — `onChange`
  only needs to fire while the last turn is `.running`, and 0 is a stable sentinel.
