# CR-02 — SliceTerminalClassifier: compaction ≠ stall, but the marker can't carry the F2 invariant

## Summary

`classify` puts compaction detection ahead of the stall check for `status != .done`,
so for the single literal "compaction" the F2 invariant (never kill a compacting GLM
as stalled) holds. But the detector is `contains("compaction")` — a free-text
substring with no CLI contract — so any other GLM wording ("compacting",
"compressing context", "context window full") falls through to `isStalled` and is
killed once `age >= stallTimeoutSeconds`. The invariant is upheld by wording luck,
not by contract, and no test asserts compaction overrides an *exceeded* timeout.
Separately, `isInfraBackoff` runs before any status guard, so a `.done` worker whose
log mentions "429"/"busy" is misrouted to `.infraBackoff`; the empty-output →
`.stalled` branch runs before the check result, so a clean file-writing worker with a
passing check is marked stalled; and `contains("compaction")` also matches "compaction
complete", over-protecting a worker that has finished compacting and hung (the
inverse-F2 risk).

## Findings

### P0 — F2 invariant rests on a non-contract substring and is unproven under stall pressure

- **Invariant:** Never kill a compacting GLM as stalled (F2).
- **Evidence:**
  - `SliceTerminalClassifier.swift:45-48` — `isCompactionMarker` is
    `haystack.contains("compaction")`: a case-insensitive substring match over
    `output`+`reasoning`. No contract binds the CLI to emit the literal "compaction".
  - `SliceTerminalClassifier.swift:35-36` — once the marker is missed, a
    `status != .done` run is decided by `isStalled`, which returns `true` when
    `age >= stallTimeoutSeconds` (`:58`). That is the kill path F2 forbids.
  - `SliceTerminalClassifierTests.swift:42-51` — the only compaction test uses a
    30s-old start and a `packet()` with default `stallTimeoutSeconds`. It proves the
    marker is *detected*, not that compaction *overrides an exceeded stall timeout*.
    A regression that reorders the checks or narrows the detector passes CI silently.
- **Risk:** If GLM emits "compacting" (note: does **not** contain "compaction"),
  "compressing context", "summarizing history", or no marker, the run is classified
  `.stalled` and killed. "compacting" vs "compaction" is a one-suffix difference and
  a likely GLM phrasing.
- **Suggested fix:**
  1. Add a structured compaction signal from the CLI (sentinel line, exit-reason
     enum, or `isCompacting` on `WorkerRunOutcome`) and detect that, not prose.
  2. Add the invariant test: `status == .running` + compaction marker + `age >=
     stallTimeoutSeconds` → `.compacting`.
- **Suggested slice:** Structured compaction marker + F2 invariant test

### P1 — `isInfraBackoff` misclassifies `.done` workers

- **Invariant:** A finished worker is judged by its check result, not by incidental
  substrings in its log.
- **Evidence:**
  - `SliceTerminalClassifier.swift:30` — `if isInfraBackoff(outcome) { return
    .infraBackoff }` is unconditional on `status`.
  - `SliceTerminalClassifier.swift:50-53` — `isInfraBackoff` scans
    `errorReason`+`output` for "429"/"busy"/"rate limit" with no status guard.
- **Result:** A `.done` worker whose output says "recovered from 429" or "queue was
  busy" returns `.infraBackoff` before the done-path runs. A successful, verified run
  is misrouted to backoff.
- **Suggested fix:** Guard `isInfraBackoff` with `outcome.status != .done`, or move
  it below the done-path.

### P1 — Empty output → `.stalled` ignores the check result

- **Invariant:** A verified run is `passed`, regardless of stdout volume.
- **Evidence:** `SliceTerminalClassifier.swift:37-38` — `if visible.isEmpty { return
  .stalled }` runs before the check is evaluated at `:39-42`.
- **Result:** A worker that does its work by writing files (no stdout), exits `.done`
  with `check.exitCode == 0`, is classified `.stalled`, not `.passed`. The check
  result is discarded; verified work can be killed/retried.
- **Suggested fix:** Evaluate the check first; only fall back to `.stalled` on empty
  output when the check also fails/is skipped — or drop the heuristic now that
  `CheckResult` is the source of truth.

### P1 — `infraBackoff` precedence over compaction misroutes compacting workers

- **Invariant:** A compacting worker is reported as compacting, not as a backoff.
- **Evidence:** `SliceTerminalClassifier.swift:30` runs before `:31-34`.
- **Result:** A compacting worker whose output also contains "429" (e.g. "compaction
  triggered after 429") returns `.infraBackoff`, not `.compacting`. F2 strictly holds
  (`.infraBackoff` ≠ `.stalled`), but the supervisor may back off/retry a worker
  that should simply be waited on.
- **Suggested fix:** Check compaction before infraBackoff, or scope infraBackoff to
  non-compacting runs.

### P1 — "compaction completed" false positive masks a stuck worker (inverse F2)

- **Invariant:** A worker that is *no longer* compacting but is stuck must remain
  reapable as stalled.
- **Evidence:** `SliceTerminalClassifier.swift:47` — `contains("compaction")` matches
  past-tense/completed forms ("compaction complete", "compaction finished").
- **Result:** A worker that wrote "compaction complete" and then hung (still
  `status == .running`) is `.compacting` indefinitely and never reaped. The brittle
  marker over-protects a worker that should be killed.
- **Suggested fix:** Match an active-compaction phrase or — preferably — the
  structured marker from P0.

### P1 — "busy" substring is too broad

- **Invariant:** `infraBackoff` should reflect a real rate-limit/backoff signal.
- **Evidence:** `SliceTerminalClassifier.swift:52` — `text.contains("busy")`.
- **Result:** Matches "busybox", "busy loop", "the user is busy". False-positive
  `.infraBackoff` on unrelated output.
- **Suggested fix:** Use a structured signal or tighter patterns ("rate limit"/"429"
  only).

### P2 — `isStalled` returns `true` when `startedAt` is nil

- **Evidence:** `SliceTerminalClassifier.swift:56` — `guard let started =
  outcome.startedAt else { return true }`.
- **Result:** A running worker with no recorded start time is assumed stalled. If
  `startedAt` is ever unset for a freshly-started run, it is reaped immediately.
  (Compaction is checked first, so a compacting worker with nil `startedAt` is still
  protected — this only affects non-compacting runs.)
- **Suggested fix:** Default to not-stalled when `startedAt` is nil, or stamp
  `startedAt` at dispatch so nil is never legal.

### P2 — Inconsistent field coverage between compaction and infraBackoff

- **Evidence:**
  - `SliceTerminalClassifier.swift:45-48` scans `output` + `reasoning`.
  - `SliceTerminalClassifier.swift:50-53` scans `errorReason` + `output`.
- **Result:** A compaction marker in `errorReason` is missed (an F2 gap); an infra
  signal in `reasoning` is missed. The two detectors disagree on which fields are
  authoritative.
- **Suggested fix:** Both scan the same union (`output`+`reasoning`+`errorReason`),
  or — with P0 — both consume structured fields.

### P2 — `isCompactionMarker` is `public`

- **Evidence:** `SliceTerminalClassifier.swift:45` — `public static func`.
- **Result:** Exposes a brittle implementation detail as public API; callers could
  depend on the substring behavior.
- **Suggested fix:** Make `private` (like `isInfraBackoff` and `isStalled`).

## Suggested missing test cases

Ordered by invariant value:

1. **F2 invariant proof (critical):** `status == .running` + compaction marker +
   `age >= stallTimeoutSeconds` → `.compacting`. No test today asserts compaction
   overrides an exceeded timeout.
2. **"compacting" wording** (running + old) → currently `.stalled`; documents the P0
   false-negative.
3. **Compaction marker in `reasoning` only** (output nil) → `.compacting`.
4. **Compaction marker in `errorReason` only** → currently `.stalled`/`.failed`
   (documents the P2 field-union gap).
5. **`status == .done` + "compaction" in output** → should not be `.compacting`
   (pins the `status != .done` guard).
6. **infraBackoff on a `.done` worker** ("429" in output, exit 0) → should be
   `.passed`, currently `.infraBackoff` (P1).
7. **"busy" false positive** on a `.done` worker → should be `.passed`/`.failed`,
   currently `.infraBackoff` (P1).
8. **Empty output + `check.exitCode == 0`** (file-writing worker) → currently
   `.stalled`, should be `.passed` (P1).
9. **Empty output + `check.skipped`** → currently `.stalled`; pin intended behavior
   (P1).
10. **`check.skipped` + non-empty output** → `.passed` (branch at `:39` uncovered).
11. **`check.timedOut`** → `.failed` (branch at `:40` uncovered).
12. **infraBackoff + compaction both present** (running) → pin precedence (P1).
13. **"compaction complete" while running + old** → should be `.stalled` once past
    compaction, currently `.compacting` forever (P1 inverse-F2).
14. **Running + nil `startedAt`** → currently `.stalled` (pins the P2 default).

## False alarms ruled out

- **Compaction-vs-stall ordering is correct for `status != .done`.** The compaction
  branch (`:31-34`) precedes the stalled branch (`:35-36`), so for the known marker a
  running compacting worker is never `.stalled`. The P0 is about brittleness and
  missing proof, not a wrong order. No reorder is suggested.
- **`.done` + compaction marker falls through to the done-path.** Correct: a finished
  worker should not be classified compacting. The `status != .done` guard is right.
- **`lowercased()` haystack.** Case-insensitive matching is correct; not a finding.
- **`trimmingCharacters(in: .whitespacesAndNewlines)`.** Whitespace-only output is
  correctly treated as empty; not a finding.
